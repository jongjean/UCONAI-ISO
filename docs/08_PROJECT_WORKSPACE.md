# 8. Project Workspace

Date: 2026-05-03
Status: Policy and preview implementation started

## Objective

Each ISO project must be independent. A project stores deliverable type, stage, track, committee context, members, document state, roadmap, references, figures, AI history, and exports.

## Setup Fields

| Field | Requirement |
|---|---|
| Title | High-risk, must be change-controlled |
| Deliverable type | IS, TS, TR, PAS, IWA, Guide or configured type |
| Track | 18, 24 or 36 month track |
| Current stage | PWI, NP, WD, CD, DIS, FDIS, publication |
| Committee | Project committee context |
| Language | Canonical document language and dialogue language |

## Completion Criteria

- Project creation validates required fields.
- Track changes can be previewed before saving.
- The project dashboard shows progress, next mission, blockers and warnings.
- Deliverable type guidelines separate IS, TS, TR, PAS/IWA and Guide behavior.

## Deliverable Guideline Matrix

| Deliverable | Workspace implication |
|---|---|
| IS | Normative, formal package evidence-heavy path |
| TS | Technical maturity path with possible future IS conversion |
| TR | Informative path; avoid hidden requirement language |
| PAS/IWA | Accelerated or workshop-driven path with tight issue tracking |
| Guide | Guidance wording and non-requirement discipline |
